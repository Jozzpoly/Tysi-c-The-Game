# Cross-Project Donor Bridge

## Why Tysiac is useful

Tysiac is a compact laboratory for interaction truth because the objects and consequences are bounded. Cards can be acquired, manipulated, ordered, constrained, committed, transferred and scored without the geometric complexity of a full 3D world.

The goal is not to make other projects look like a card game. The goal is to extract interaction principles that remain valid when the object changes.

## Shared project pattern

Across the Owner's projects, the desired direction repeatedly favors:

- direct manipulation over mode-heavy indirect control;
- world/object-first interaction over dashboard-first UI;
- local meaning attached to the thing that causes it;
- visible affordance matching actual input activation;
- fast build/edit -> run -> observe -> change loops;
- preserving physical authority, collisions, leverage and consequence instead of teleporting objects to satisfy input;
- diagnostics that explain cause without becoming the main visual product;
- interfaces that expose possibilities without deciding for the Owner what is allowed;
- feedback that remains truthful under latency, failure and uncertainty.

Tysiac should turn those recurring instincts into a more explicit interaction science.

## Tysiac -> Jozz Vehicle / builder

### Card lesson

A card should be directly acquired, manipulated, constrained and committed while preserving identity and user organization.

### Builder transfer

A vehicle component should likewise:

- respond immediately to direct grab;
- preserve a meaningful grab point/pivot;
- express constraints through geometry/behavior rather than modal error text;
- distinguish exploratory positioning from committed topology change when necessary;
- preserve Owner-created spatial organization;
- allow intentional absurd constructions unless program safety is actually threatened;
- show the causal effect of parameter/topology changes in the shortest possible edit -> run -> observe loop.

The donor is not `drag and drop`. The donor is **embodied manipulation with truthful constraints and retained agency**.

## Tysiac -> JES / world-matter interaction

### Card lesson

The interface should not be louder than the object. Routine rules should become discoverable through the behavior of the manipulated thing.

### JES transfer

Matter/Meaning interactions should prefer:

- visible affordance where interaction is actually possible;
- direct local feedback at the contact/meaning site;
- no hidden clickable candidate that presentation denies;
- no dashboard metric substituting for observable world consequence;
- local causal traces for forces, support, bearing, torque or other phenomena when those become relevant;
- diagnostics layered over a world-first representation rather than replacing it.

The donor is **truthful coincidence between affordance, activation and consequence**.

## Tysiac -> Multi World

### Card lesson

Object feel depends on directness, mass/constraint coherence, cancellation, ownership transfer and the relation between the user's hand and the object's motion.

### Multi World transfer

Physical object manipulation should be judged using the same dimensions:

- contact acquisition;
- positional directness;
- rotational ownership;
- inertia and damping;
- collision consequence;
- transfer between held/free/attached states;
- predictable cancel/release;
- clear causal relation between input and object reaction;
- multiplayer authority correction that does not visually rewrite history without explanation.

Prior manipulation work already showed that direct intent-first grabbing can unlock exploration while poor rotational ownership and actuator instability can make the object feel chaotic rather than embodied. Tysiac provides a simpler place to formalize those dimensions before reapplying them to 3D manipulation.

## Tysiac -> LLM Live NPC

The donor is less about direct manipulation and more about **perceptual truth and explainable causality**.

A living NPC interface/debug layer should show:

- what the NPC could perceive;
- what it actually perceived;
- what it remembered;
- what caused a decision;
- what action was attempted;
- what the world accepted;
- what consequence followed.

This should remain layered and inspectable without turning the game into an AI dashboard.

The shared principle is the same causal chain:

`world fact -> perceived fact -> internal interpretation -> intention -> action -> authority/world response -> visible consequence`

## Donor candidates worth proving in Tysiac

The following are stronger donor targets than visual components:

### A. Reversible manipulation envelope

How to let users touch, move, inspect and reorganize an object instantly without falsely committing system state.

### B. Commit boundary language

How an interaction transitions from exploration into an irreversible/authoritative command without hidden mode switches.

### C. Constraint-as-behavior

How legality and system boundaries can be felt before they need to be explained in prose.

### D. User-owned workspace

How system updates preserve spatial organization that the user created for cognition.

### E. Before/event/after choreography

How canonical state changes become perceptually continuous without making presentation a second authority.

### F. Attention-through-causality

How cause itself routes attention toward consequence instead of using banners and global highlights.

### G. Failure dignity

How cancel, reject, reconnect, latency and correction remain part of the same interaction grammar.

### H. Quiet-life feedback

How a system can feel inhabited and responsive between major events without constant decorative animation.

## Important non-transfer rule

Do not automatically transplant:

- card fan geometry;
- spring constants;
- glow language;
- sound palettes;
- gesture shapes;
- UI components;
- visual themes.

Transfer semantic/causal principles first. Re-embody them in the target project's own world and interaction body.

## Success condition

Tysiac becomes a meaningful donor only when a principle survives three tests:

1. it improves Tysiac under repeated real use;
2. it can be described without card-game vocabulary;
3. it can be re-expressed in a materially different project without importing the original implementation.

Until then, call it a Tysiac finding, not a universal principle.
