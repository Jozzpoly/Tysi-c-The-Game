# Experience Foundation Campaign Map

Status: living research map. Runs may split, merge, reorder or repeat when evidence demands it.

This campaign exists because one message / one redesign / one animation pass is not enough to discover the experience language of the game.

The campaign deliberately separates **experience truth** from **game truth**. The Owner can be a primary judge of tactile, visual and temporal feel without being a Tysiąc rules authority.

## Phase A — Embodiment

### Run 01 — Card Object + Hand

Question: can a playing card feel physically present and can the player's hand feel like owned, manipulable territory?

Topics:
- contact, hold, drag, lift, tilt, spring, mass;
- hand deformation;
- manual ordering;
- insert/remove behavior;
- play-vs-reorder gesture disambiguation;
- safe probing;
- latency/rejection truthfulness.

Promotion target: a small set of interaction primitives, not a final UI.

### Run 02 — Commit and Constraint

Question: can the player feel the difference between touching, exploring, aiming and irreversibly committing an action?

Topics:
- commit thresholds;
- legal/illegal material language;
- cancel behavior;
- target magnetism;
- mistake resistance;
- server pending / accept / reject states.

### Run 03 — First-Person Hand Intelligence

Question: can the hand itself become a high-bandwidth teaching and thinking surface?

Topics:
- local visual grouping;
- manual order persistence;
- contextual relationships between cards;
- subtle legal affordance;
- inspection;
- new-card staging;
- personal organization versus canonical sorting.

## Phase B — Social / spatial presence

### Run 04 — Opponent Presence

Question: can opponents feel present without avatars, fake emotion or UI theater?

Topics:
- source seat readability;
- temporal personality without strategy leakage;
- opponent hand / card-back motion;
- ownership transfer;
- waiting states;
- action origin and consequence;
- remote human versus bot presentation parity unless intentionally differentiated.

### Run 05 — Trick as Scene

Question: can one complete trick become a legible, satisfying mini-scene rather than three state updates?

Topics:
- three-card spatial composition;
- temporal tension;
- winning-card readability;
- collection;
- point ownership;
- next lead;
- common-loop fatigue.

### Run 06 — Table / Arena Topology

Question: what is the minimum spatial world required to understand three-player relationships without falling back to a traditional green table?

Topics:
- territories;
- distance / perspective;
- center versus distributed play;
- score location;
- current actor;
- desktop/mobile topology divergence.

## Phase C — Learning without tutorial chrome

### Run 07 — Self-Teaching Interaction Language

Question: can a novice discover routine play through affordance, probing, constraint and consequence?

Topics:
- mechanical discoverability;
- local rule legibility;
- failed-probe explanations;
- next-action availability;
- opponent demonstration;
- tutorial-free first minutes.

### Run 08 — Information / Attention Grammar

Question: can the game guide attention without arrows, banners or constant animation?

Topics:
- local salience;
- peripheral information;
- interruption recovery;
- quiet versus active regions;
- gaze path / pointer path observations;
- accessibility alternatives.

## Phase D — Stakes and dramaturgy

### Run 09 — Auction / Commitment Pressure

Question: how should increasing commitment and risk feel before we judge whether the Tysiąc strategy itself is good?

Topics:
- number / bid materiality;
- opponent pressure;
- passing;
- winning the auction;
- ownership of the next phase;
- increasing stakes without loud HUD banners.

### Run 10 — Marriage / Trump World Change

Question: how should a rule event that changes the meaning of future cards transform the perceptual world?

Topics:
- source cards;
- suit identity;
- trump persistence;
- point award;
- escalation level;
- no ambiguity between temporary effect and persistent rule state.

### Run 11 — Scoring / Contract Consequence

Question: can score changes feel causally grounded and emotionally proportional?

Topics:
- source of points;
- contract made / failed;
- defender scoring;
- stable residue;
- negative consequence without punitive visual noise;
- on-demand explanation.

### Run 12 — Exceptional Events

Question: how should rare events such as bomb, four nines or match completion break normal grammar without becoming incoherent spectacle?

Topics:
- hierarchy reserve;
- interruption rights;
- anticipation versus surprise;
- confirmation requirements;
- reset / settle.

## Phase E — Sensory system

### Run 13 — Sound as Material

Question: can audio make card movement, contact, ownership and consequence more physically legible rather than merely more exciting?

Topics:
- contact / slide / drop layers;
- spatial source;
- pitch / timbre hierarchy;
- silence;
- repeated-action fatigue;
- muted mode equivalence.

### Run 14 — Haptics as Reinforcement

Question: where does optional haptic feedback materially improve embodiment?

Topics:
- grab;
- commit notch;
- invalid boundary;
- important consequence;
- platform availability;
- no critical information carried only by vibration.

### Run 15 — Motion Grammar

Question: can motion communicate identity, ownership, constraint and state transition consistently across the game?

Topics:
- continuity;
- source/destination;
- spring families;
- duration by frequency and importance;
- reduced motion;
- cosmetic tail versus causal hold.

## Phase F — Platform embodiment

### Run 16 — Mobile Body

Question: how does the phone become a physical playing surface instead of a 390 px viewport?

Topics:
- thumb reach;
- finger occlusion;
- card lift above touch point;
- safe areas;
- portrait density;
- optional haptics;
- touch cancellation;
- one-hand versus two-hand posture.

### Run 17 — Desktop Body

Question: how do hover, precise pointer control and large space create a distinct but semantically consistent experience?

Topics:
- hover preview;
- click/drag acquisition;
- pointer distance;
- wider territories;
- keyboard alternatives;
- large-screen attention distribution.

## Phase G — Torture / integration

### Run 18 — Repetition and Fatigue

Question: what survives 100 ordinary interactions?

Tests:
- common trick loops;
- reordering spam;
- rapid cancel/regrab;
- sound fatigue;
- motion fatigue;
- long session;
- distracted play;
- 0.5x / 1x / accelerated instrumentation.

### Run 19 — Latency / Reconnect / Truth

Question: does the experience remain coherent when the network is imperfect?

Tests:
- low/medium/high latency;
- command rejection;
- duplicate response;
- reconnect during calm;
- reconnect during presentation sequence;
- snap-to-authority;
- no hidden-state leak.

### Run 20 — Integrated Experience Candidate

Only here do we assemble promoted primitives into the real runtime as a coherent experience candidate.

This is not final art polish. It is the first evidence-backed integrated language.

## How a run ends

A run does not end because a prototype exists.

It ends when one of these is true:
- **REJECTED** — hypothesis did not materially improve experience;
- **PRIMITIVE RETAINED** — a narrow behavior earned promotion, while the wider concept did not;
- **ADEQUATE FOR INTEGRATION** — evidence is strong enough to move the primitive into real runtime;
- **OPEN / NEEDS MORE TORTURE** — novelty, fatigue, platform or truth questions remain unresolved.

## Owner feedback protocol

The Owner should not be forced into design vocabulary.

Preserve raw language such as:
- `martwe`;
- `mięsiste`;
- `karta się klei do palca`;
- `plastik`;
- `nie wiem co się stało`;
- `wiedziałem co zrobić bez myślenia`;
- `za dużo się odpierdala`;
- `to było zajebiste, ale po piątym razie wkurwia`.

Interpretation belongs in a separate layer.

## Cross-project value

The campaign is locally about Tysiąc, but validated principles may later inform other projects, especially where these properties matter:
- direct manipulation;
- live causal feedback;
- embodied objects;
- state truthfulness;
- non-paternalistic interaction;
- visual explanation instead of textual ceremony;
- latency-aware presentation;
- owner-driven qualitative evidence.

Local solutions must not be copied blindly across projects. Only well-supported principles should transfer.
